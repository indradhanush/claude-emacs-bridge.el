#+title: Project Session Routing
#+date: 2026-08-21

* Objective

Extend the Claude Emacs bridge so each Doom project can select an active
Claude Code session as its target. The first send for a project asks for a
target, later sends reuse that target while it remains active, and a separate
command replaces the association on demand. Associations last only for the
current Emacs process.

* Acceptance Criteria

- [X] Emacs can request and display the active local Claude Code sessions that
  the coordinator can reach.
- [X] The coordinator session itself is not offered as a target.
- [X] A project without an association prompts for a target before sending.
- [X] A project with a live associated target sends without prompting.
- [X] A stale association is cleared and replaced before another message is
  sent.
- [X] A separate interactive command replaces the current project's target.
- [X] Context identity uses the first available namespaced key in this order:
  Emacs project root, perspective name, Git root, then =default-directory=.
- [X] Root and directory keys are expanded and normalized before lookup.
- [X] Associations are held in memory and do not survive Emacs restarts.
- [X] Picker labels include PID so sessions remain distinguishable, while the
  CLI-provided live name is used for coordinator routing.
- [X] No target session name is hardcoded in generated prompts.
- [X] The coordinator session always starts with
  =--model claude-haiku-4-5-20251001=.
- [X] Every introduced helper has a direct ERT test.
- [X] Tests pass in isolated Emacs and the running Doom Emacs instance.
- [ ] Live verification covers initial selection, default reuse, stale-target
  handling, and explicit reassignment between two active sessions.
- [X] The bridge and its ERT tests live in the standalone
  =~/github.com/claude-emacs-bridge= repository.
- [X] Package symbols use the =claude-emacs-bridge-= prefix, with
  =claude-emacs-bridge--= reserved for internal functions and variables.
- [X] Doom loads the local package with =use-package!= and no longer owns a
  sibling bridge library or bridge test file.
- [X] A send with no running coordinator logs the missing-coordinator status
  and asks whether to start it.
- [X] Accepting the prompt starts the coordinator and continues the original
  send without asking for the instruction again.
- [X] Declining the prompt stops without resolving a target or sending data.
- [X] A running coordinator preserves the direct send path without prompting.
- [X] Auto-start preserves the source file and routing context after vterm
  switches the current buffer to the coordinator.

* Verified Facts

- Claude Code 2.1.238 exposes =/list-agents= inside an eligible interactive
  session and lists other active local sessions.
- Claude Code 2.1.238 exposes =claude agents --json= for machine-readable
  discovery of active interactive and background sessions.
- Each JSON row includes =pid=, =cwd=, =kind=, and =startedAt=. Interactive
  rows may include =sessionId=, =name=, =status=, and =waitingFor=.
- =claude agents --json= does not expose the internal SendMessage address or
  =ListAgents= reference. Live names are made unique by Claude Code when needed.
- The coordinator can be excluded reliably by comparing the JSON =pid= with
  the vterm subprocess PID. Filtering by its mutable name is not reliable.
- Claude Code's =ListAgents= and =SendMessage= tools are available to the model,
  not directly to the current Emacs Lisp integration.
- Duplicate live session names may require the short address that Claude Code
  supplies during listing.
- The bridge formats the selected session's live name into each coordinator
  prompt.
- Doom workspaces are backed by =persp-mode=. =+workspace-current-name= delegates
  to =safe-persp-name= and the current perspective.
- For =~/.config/doom/config.el=, Emacs project identity resolves to
  =~/.config/= while Git identity resolves to =~/=.
- For =~/org-roam/projects.org=, Emacs project identity and Git identity both
  resolve to =~/org-roam/=, and its perspective is =org-roam=.
- The installed Claude Code CLI supports =--model <model>=. The coordinator's
  required model identifier is =claude-haiku-4-5-20251001=.
- A live coordinator launch upgraded Claude Code to 2.1.239, preserved the
  discovery fields, and displayed =Haiku 4.5 · Claude Team=.

* Decisions

- [2026-08-21] Keep associations in memory for this proof of concept because
  only currently active sessions are valid targets.
- [2026-08-21] Prefer Emacs's project API over Projectile-specific calls so the
  bridge remains Doom-neutral. Fall back to the current perspective, Git root,
  then normalized =default-directory=.
- [2026-08-21] Keep context-key sources namespaced to prevent accidental
  collisions between project, workspace, Git, and directory identities.
- [2026-08-21] Pin the coordinator to Claude Haiku 4.5 with the full model
  identifier rather than relying on a mutable alias or user default.
- [2026-08-21] Discover sessions with =claude agents --json=. Keep PID plus
  =startedAt= as the transient identity, exclude the coordinator by PID, and
  route with Claude's live unique session name.
- [2026-08-21] Require explicit selection and never infer a target from cwd,
  recency, or naming conventions.
- [2026-08-21] Keep session listing and target replacement as separate commands
  from sending.
- [2026-08-21] Match the library, feature, and global symbol prefix to
  =claude-emacs-bridge=. Use two hyphens for internal symbols, following Emacs
  Lisp naming conventions.
- [2026-08-21] Keep the package local and load it through Doom's
  =use-package!= rather than introducing package-manager metadata or remote
  installation.

* Blockers / Open Questions

- None.

* Rejected Approaches

- Hardcoded target names: cannot support multiple projects or sessions.
- Persistent associations: unnecessary for this proof of concept and prone to
  stale targets after restart.
- Automatic target guessing: can silently send project context to the wrong
  session.
- Interactive TUI scraping: fragile; retain only as an explicitly approved
  fallback if supported discovery is unavailable.
