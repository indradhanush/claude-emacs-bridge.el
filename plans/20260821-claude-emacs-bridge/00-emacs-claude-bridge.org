* Objective

Build an Emacs command that uses the active region or current line to identify
an inclusive line range, then sends that range, the absolute file path, and a
minibuffer instruction to a dedicated Claude Code coordinator. The coordinator
forwards the message to a selected local Claude Code session through native
cross-session messaging. The selected text itself is not sent.

* Acceptance Criteria

- [X] An interactive command rejects buffers without a visited file.
- [X] Without an active region, the command sends the current line number.
- [X] The target payload contains the absolute file path, inclusive start and
  end line numbers, instruction, and ACK-only completion requirement.
- [X] A region ending at the beginning of a line reports the preceding selected
  line as its inclusive end line.
- [X] A command starts or reuses a dedicated =*claude-emacs-server*= vterm
  running the Claude Code session named =emacs-server=.
- [X] The coordinator process starts without =DO_NOT_TRACK= so cross-session
  messaging can be enabled without changing Emacs's global environment.
- [X] Every introduced helper has a direct ERT test.
- [X] Tests pass in the running Doom Emacs instance.
- [X] A live proof sends the expected path, lines, and instruction to =task-1=
  without sending the selected text.

* Decisions

- [2026-08-21] Use Claude Code native cross-session messaging through a dumb
  coordinator because it avoids API, MCP, channel, and private socket
  integrations.
- [2026-08-21] Use a dedicated Emacs vterm because Emacs can send input directly
  to a process it owns.
- [2026-08-21] Keep the proof of concept available through =M-x= commands only;
  defer keybindings and response presentation.
- [2026-08-21] Unset =DO_NOT_TRACK= only for the coordinator process rather than
  changing the global Emacs environment.

* Constraints

- Claude Code may paraphrase the forwarding prompt even when asked to preserve
  it. The path, line range, and instruction remain explicit.
- The receiving session retains its own permission checks.

* Rejected Approaches

- Claude API: explicitly unavailable for this work.
- Custom MCP or channel plugin: unnecessary for the local proof of concept.
- Direct inbox-socket client: depends on lower-level authentication and framing.
- Terminal keystroke injection into an external terminal: more fragile than an
  Emacs-owned vterm process.
